### Tugas 3

1. Data delivery dibutuhkan karena sebuah platform biasanya terdiri dari beberapa bagian yang terpisah, misalnya backend Django dan tampilan front-end atau aplikasi lain, yang perlu saling bertukar data. Tanpa mekanisme data delivery, data yang tersimpan di database (lewat model, seperti `Project` dan `Experience` pada proyek ini) hanya bisa diakses lewat render HTML biasa dan tidak bisa dikonsumsi oleh klien lain seperti aplikasi mobile atau layanan pihak ketiga. Dengan menyediakan data dalam format terstruktur seperti JSON lewat endpoint `api/projects/` (fungsi `get_projects_json` di `main/views.py`), data yang sama bisa digunakan ulang oleh berbagai jenis klien tanpa harus menduplikasi logika pengambilan data.

2. Menurut saya JSON lebih baik dibandingkan XML untuk kebutuhan proyek ini. JSON strukturnya lebih ringkas (tidak perlu closing tag seperti XML) sehingga ukuran datanya lebih kecil dan lebih cepat diparsing, terutama saat dikirim lewat jaringan. JSON juga native dipetakan ke struktur data JavaScript (object dan array), sehingga lebih mudah dikonsumsi langsung di sisi front-end tanpa parsing tambahan. Django sendiri juga menyediakan `serializers.serialize("json", ...)` yang saya pakai langsung di `get_projects_json`, membuat implementasinya jauh lebih sederhana dibanding harus membangun struktur XML secara manual. XML unggul untuk kasus yang membutuhkan validasi struktur ketat (lewat XML Schema) atau dokumen dengan metadata kompleks, tapi untuk pertukaran data API sederhana seperti pada aplikasi ini, JSON adalah pilihan yang lebih efisien.

3. Method `is_valid()` pada Form Django menjalankan seluruh proses validasi terhadap data yang dikirim pengguna, mulai dari validasi bawaan tiap field (misalnya `URLField` memastikan `link` berformat URL yang benar, atau field wajib tidak boleh kosong) hingga validasi custom yang saya definisikan sendiri jika ada. Method ini mengembalikan `True` hanya jika semua data lolos validasi, dan jika tidak, error dari masing-masing field akan tersimpan di `form.errors` sehingga bisa ditampilkan kembali ke pengguna (seperti pada `{% for error in field.errors %}` di `projects_form.html`). Saya membutuhkan `is_valid()` di `create_project` (`main/views.py`) supaya data yang tidak valid tidak pernah sampai disimpan ke database lewat `form.save()`, menjaga integritas data tanpa saya harus menulis validasi manual satu per satu.

4. `csrf_token` adalah token unik yang digenerate Django untuk setiap sesi dan disisipkan sebagai hidden input pada form (seperti pada `{% csrf_token %}` di `projects_form.html`). Fungsinya adalah mencegah serangan Cross-Site Request Forgery, yaitu ketika situs lain yang berbahaya mencoba mengirimkan request (misalnya POST) atas nama pengguna yang sedang login ke aplikasi ini tanpa sepengetahuan mereka. Django akan menolak request POST yang tidak menyertakan token CSRF yang valid dan cocok dengan sesi pengguna. Saya membutuhkannya di form `create_project` karena form tersebut mengubah data (menambah `Project` baru ke database), sehingga harus dipastikan request tersebut benar-benar berasal dari form aplikasi ini, bukan dari sumber luar yang mencoba menyisipkan data secara paksa.

Kedua, saya menambahkan view `create_project` di `main/views.py` yang menampilkan form kosong saat request `GET`, dan memvalidasi serta menyimpan data lewat `form.save()` saat `POST` valid, lalu redirect ke halaman `/projects/` disertai pesan sukses lewat Django `messages` framework. Ketiga, saya membuat template `projects_form.html` yang extend `base.html`, menampilkan setiap field form beserta error-nya, dan menyertakan `{% csrf_token %}` di dalam tag `<form>`. Keempat, saya menambahkan route baru `projects/add/` di `main/urls.py` yang mengarah ke `create_project`, serta tombol "Tambah Proyek" di `projects.html` yang mengarah ke route tersebut. Kelima, untuk data delivery saya menambahkan fungsi `get_projects_json` yang men-serialize queryset `Project` ke JSON, lalu mendaftarkannya di route `api/projects/`, dan memanfaatkannya kembali di dalam `show_projects` supaya proses pengambilan data konsisten baik untuk tampilan HTML maupun endpoint API. Setelah semua langkah selesai saya menguji secara manual lewat `python manage.py runserver`, memastikan form berhasil menambah data baru, validasi error tampil dengan benar saat input kosong, dan endpoint `/api/projects/` mengembalikan data JSON yang sesuai.
